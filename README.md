# EFT 背包與倉庫規劃

網頁使用瀏覽器儲存配置；計算交由同一台主機的 OR-Tools CP-SAT 求解服務。

## 啟動

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python server.py
```

服務綁定 `0.0.0.0:49237`，同時提供靜態網頁及 `/api/solve`。
單純用靜態 HTTP server 開啟網頁時，無法使用最佳化功能。

## 最佳化目標

1. 最大化放入的背包數量（可行時全部放入）。
2. 最大化最外層空格：出征模式看主包內部；倉庫模式看倉庫。
3. 不犧牲以上目標，盡量放入彈掛。

模型直接決定父容器、分區、座標及旋轉。二維不重疊、外部尺寸、巢狀深度、同款套包限制及分區邊界都是硬性條件。
相同背包使用對稱性限制，避免重複探索不同的標號或放入順序。

只有求解器回傳 `OPTIMAL` 才會標示最佳解已證明；`FEASIBLE` 只代表目前可行方案。
每次求解最多 15 秒、150 件裝備、20,000 個候選容器關係，超出規模會提示分批規劃。
停止搜尋或變更配置會中止該次求解。舊分支沒有後端時，已安裝的 user systemd 啟動器會退回靜態服務。

## 驗證

```bash
.venv/bin/python -m unittest discover -s tests -v
```

測試包含獨立窮舉對照、旋轉與分區限制、間接同款套包禁令、巢狀空間最佳化及重複物品效能。
