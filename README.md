# EFT 倉庫背包規劃

網頁使用瀏覽器儲存配置；計算交由同一台主機的 OR-Tools CP-SAT 求解服務。

## 啟動

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python server.py
```

服務綁定 `0.0.0.0:49237`，同時提供靜態網頁及 `/api/solve`。
單純用靜態 HTTP server 開啟網頁時，無法使用最佳化功能。

## 最佳化目標

1. 最大化放入的背包數量（可行時全部放入）。
2. 最大化倉庫剩餘空格。

模型直接決定父容器、分區、座標及旋轉。二維不重疊、外部尺寸、巢狀深度、同款套包限制及分區邊界都是硬性條件。
模型縮減方式：

- 先建立尺寸相容關係，排除無法從倉庫到達或超過最大層數的候選容器。
- 收納規則相同的型號與配色共用對稱性限制；保留每件裝備的原始型號。
- 同款同層的兄弟包只保留一種座標排序，避免交換標號重算。
- 座標只保留其他裝備邊長加總形成的緊密排列位置，不逐格探索等價空隙。
- 座標加總以位元集合計算，同尺寸、同座標範圍的裝備共用單次求解內的快取。
- 全部背包收納規則相同、能互相套入且每包最多容納一個子包時，先精確縮減成填滿深度的套包鏈，再求解外層排列。仍保留每個背包的原始資料與預覽層級；混合規格、可分叉或有同款禁令時使用完整模型。
- 每個分區加入外部面積總和上限，整棵套包樹加入剩餘空間上限，提早排除不可能或無法改善目標的結構。
- 同一件裝備共用座標終點，減少候選容器各自產生的變數。

搜尋分支是求解器內部統計，不是產生或儲存的配置筆數。上述縮減保留最佳解；一般混合配置仍由同一個約束模型同時處理結構與擺放，沒有先固定貪婪套包結構。

只有求解器回傳 `OPTIMAL` 才會標示最佳解已證明；`FEASIBLE` 只代表目前可行方案。
自動分析每次最多 15 秒；單次配置最多 150 個背包、20,000 個候選容器關係，超出規模會提示分批規劃。
變更配置會中止該次求解。舊分支沒有後端時，已安裝的 user systemd 啟動器會退回靜態服務。

## 分析控制

- **停止分析**：通知求解器停止，取得最後的分支數，保留目前最佳方案。
- **繼續分析**：使用目前最佳方案的變數值作為求解提示，解除 15 秒時間限制；仍遵守尺寸、收納規則、配置規模及記憶體設定。
- **重新分析**：清除目前方案與累計數，以標準時間限制重新開始。

CP-SAT 不提供保存並恢復內部搜尋樹的介面，因此繼續分析會重新啟動求解，以先前方案作為起點；介面保留較好的方案，累加各次求解回報的分支數。這個數字是查找工作量，不是不重複配置的數量。
查找總數在分析中、完成、停止及錯誤時持續顯示。更換裝備或設定、或按重新分析時歸零；配置不變時切換選單不會自動重啟。

## 驗證

```bash
.venv/bin/python -m unittest discover -s tests -v
```

測試包含獨立窮舉對照、旋轉與分區限制、間接同款套包禁令、巢狀空間最佳化、不可達容器及相同收納規則的不同型號效能。

單鏈縮減效能紀錄（同機三次中位數，包含模型建立與結果還原）：背包外部及內部均為 4×5，倉庫 10×28，深度 6，允許旋轉。前後都證明為最佳解。

| 背包數 | 原耗時 | 縮減後耗時 | 原搜尋分支 | 縮減後分支 |
| --- | --- | --- | --- | --- |
| 8 | 0.04594 秒 | 0.00529 秒 | 490 | 21 |
| 18 | 0.37107 秒 | 0.00627 秒 | 2,126 | 59 |
| 30 | 0.89765 秒 | 0.00929 秒 | 12,284 | 113 |

這些數值只代表上述可縮減配置，不代表混合背包也有相同加速幅度。另以 120 組同規格、旋轉、混合與部分放入配置對照修改前模型，最佳目標相同，且還原後的擺放通過幾何檢查。

## 舊資料相容

目前僅提供倉庫背包規劃。舊出征配置載入後轉為倉庫配置，保留背包數量、自訂背包、巢狀設定與倉庫尺寸。瀏覽器記憶、匯入及匯出均排除非背包項目，舊主包選項不再使用。

後端也會在建立變數及檢查背包數量上限之前排除非背包，不為它們建立座標、父容器、旋轉或計分變數。倉庫固定為最外層，模型已移除主包選擇變數與非背包目標；空清單直接回傳空倉庫，不啟動求解器。
