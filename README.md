# EFT 背包與倉庫規劃

網頁使用瀏覽器儲存配置；計算交由同一台主機的 OR-Tools CP-SAT 求解服務。

## 啟動

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python server.py
```

服務綁定 `0.0.0.0:49237`，同時提供靜態網頁及 `/api/solve`。
單純用靜態 HTTP server 開啟網頁時，無法使用最佳化功能。

## 最佳化目標

1. 最大化放入的背包數量（可行時全部放入）。
2. 最大化最外層空格：出征模式看主包內部；倉庫模式看倉庫。
3. 不犧牲以上目標，盡量放入彈掛。

模型直接決定父容器、分區、座標及旋轉。二維不重疊、外部尺寸、巢狀深度、同款套包限制及分區邊界都是硬性條件。
模型縮減方式：

- 先建立尺寸相容關係，排除無法從合法主包到達或超過最大層數的候選容器。
- 收納規則相同的型號與配色共用對稱性限制；保留每件裝備的原始型號及指定主包。
- 同款同層的兄弟包只保留一種座標排序，避免交換標號重算。
- 座標只保留其他裝備邊長加總形成的緊密排列位置，不逐格探索等價空隙。
- 每個分區加入外部面積總和上限，整棵套包樹加入剩餘空間上限，提早排除不可能或無法改善目標的結構。
- 同一件裝備共用座標終點，減少候選容器各自產生的變數。

搜尋分支是求解器內部統計，不是產生或儲存的配置筆數。上述縮減保留最佳解；一般混合配置仍由同一個約束模型同時處理結構與擺放，沒有先固定貪婪套包結構。

只有求解器回傳 `OPTIMAL` 才會標示最佳解已證明；`FEASIBLE` 只代表目前可行方案。
自動分析每次最多 15 秒；單次配置最多 150 件裝備、20,000 個候選容器關係，超出規模會提示分批規劃。
變更配置會中止該次求解。舊分支沒有後端時，已安裝的 user systemd 啟動器會退回靜態服務。

## 分析控制

- **停止分析**：通知求解器停止，取得最後的分支數，保留目前最佳方案。
- **繼續分析（無視上限）**：使用目前最佳方案的變數值作為求解提示，解除 15 秒時間限制；仍遵守尺寸、收納規則、配置規模及記憶體設定。
- **重新分析**：清除目前方案與累計數，以標準時間限制重新開始。

CP-SAT 不提供保存並恢復內部搜尋樹的介面，因此繼續分析會重新啟動求解，以先前方案作為起點；介面保留較好的方案，累加各次求解回報的分支數。這個數字是查找工作量，不是不重複配置的數量。
查找總數在分析中、完成、停止及錯誤時持續顯示。更換裝備或設定、或按重新分析時歸零；配置不變時切換選單不會自動重啟。

## 驗證

```bash
.venv/bin/python -m unittest discover -s tests -v
```

測試包含獨立窮舉對照、旋轉與分區限制、間接同款套包禁令、巢狀空間最佳化、不可達容器及相同收納規則的不同型號效能。

### 本地優化前後對照

2026-10-14，以相同 OR-Tools 版本及求解設定比較。兩版均證明最佳，放入數量與剩餘空格相同；分支數與時間會隨配置及執行環境變動。

| 配置 | 原模型分支 | 新模型分支 | 原耗時 | 新耗時 |
| --- | ---: | ---: | ---: | ---: |
| 8 個不同型號，外部與內部皆 4×5，自動選主包，最多 6 層 | 140,539 | 0 | 3.008 秒 | 0.005 秒 |
| 6 個不同型號，外部與內部皆 4×5，指定 6×8 主包 | 2,270 | 147 | 0.054 秒 | 0.015 秒 |
| 8 個同款，外部與內部皆 4×4，指定 6×8 主包 | 2,091 | 188 | 0.044 秒 | 0.019 秒 |

第一列因深度及尺寸限制，最多只能放入 6 個包；分支為 0 表示預處理就已證明最佳，仍有建立模型及求解成本。
